Repository and organization webhooks are supported. Assign an issue to the configured agent's GitHub user to start work. Issues assigned to other users are ignored. Assignment creates a Task; later eligible issue events and comments resume the same Task. The configured user must have repository access.


Merges of PRs linked to a Task wake that same Task, even in a different repository. Periodic GitHub API checks cover repositories without a configured webhook.


Email threads
The agent sends task-bound email through the controller's SMTP account. Reply normally from a recipient address: In-Reply-To and References route the IMAP reply to the original Task. Replies enqueue an attributed prompt; they do not automatically post GitHub comments. Unmatched mail does not create Tasks. IMAP_HOST and SMTP_HOST configure inbound and outbound mail independently. Mail settings come from a ConfigMap and protocol credentials from separate Secrets.




Alertmanager
Add a receiver and route the desired alerts to it. Repeated fingerprints resume the same Task; resolved notifications do not mark code work complete.




Basic webhook
POST an existing Task ID or GitHub issue URL with a stable delivery ID. Authenticate with the receiver bearer token.
